# 年度更新チェックリスト

## 1. 素材を整える

- 掲載許諾済みの写真だけを選ぶ
- 掲載NG人物が全表示幅のクロップで写らないことを確認する
- Day 1、Day 2、集合写真の時系列を確認する
- 写真を変形せずWebPへ最適化し、`assets/images/YYYY/` に置く
- 元写真、アンケート原文、共有URLはGitHubへ追加しない

## 2. 年度ページを作る

- 直近年度の `reports/YYYY/` を新年度へ複製する
- ページ本文とメタ情報に前年の年号や固有名詞が残っていないか検索する
- 年度用OGP画像を1200 x 630pxで作る
- canonical、OGP URL、構造化データ、sitemapを新年度URLへ合わせる

## 3. トップページを更新する

- 最新年度へのリンクと紹介写真を更新する
- 通年ページに年度固有の数字や詳細を増やしすぎない
- 過年度ページと募集アーカイブへの既存URLを壊さない

## 4. 表示を確認する

- 390px前後のスマートフォン
- 600pxから900pxの中間幅とiPad縦横
- 1280px以上のデスクトップ
- 顔と文字が重ならず、人物の目や顔が不自然に切れていない
- 集合写真の端にいる人物が欠けていない
- 画像が引き伸ばされず、読み込み失敗がない
- ナビゲーション、問い合わせ、外部リンクが動作する

## 5. 公開する

- ローカルでトップと年度ページを確認する
- Vercelプレビューで関係者確認を行う
- 承認後に `main` へ反映する
- GitHub Pagesのビルド完了と本番URLのHTTP 200を確認する
- 公開後にfavicon、OGP、robots.txt、sitemap.xmlを確認する

## 6. 資料版を残す

- `tools/annual-report-template/input-template.md` を新年度情報で埋める
- `examples/YYYY/` に生成コードと制作判断だけを保存する
- PPTX、PDF、プレビュー画像、元写真はコミットしない
